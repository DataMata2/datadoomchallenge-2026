# Demonstration acceptance checkpoints

This is a coordinator planning artifact, not evidence that the application works. Final script and chosen conversations follow measured evaluations.

## Five-minute narrative

1. Start with an overview and identify the selected period and conversation count. Assigned dates are visible as demonstration scheduling metadata.
2. Ask: "Compare quality for agent chats in the first and second halves of October 2026." Show visible filters, grouped results, sample counts, and the metric definition/calculation.
3. Follow up: "Now show only English conversations." Retain the period/comparison and change the language; show the updated report and underlying conversation set.
4. Open a real assessed conversation with an N/A example. Inspect one criterion's definition, raw result, effective weight, short rationale, and linked source turns. Demonstrate original timestamps and stable evidence navigation.
5. Submit an appeal, record a reviewer reason and changed/confirmed decision, and show original versus final result and recalculated total.
6. Save a changed checklist criterion through the interface and start a real evaluation on one conversation. Use the processing interval to show the saved report or briefly discuss the presentation-only local/cloud experiment.
7. Demonstrate an additional report metric over a small selected set (for example the five calls), with a visible definition, result/progress, and evidence. Confirm the base QA total stays unchanged. Prepared custom results may be used transparently; at least one fresh assessment is genuinely executed.
8. Return to the completed changed-checklist result and finish within five minutes. Avoid navigating to infrastructure configuration during the demonstration.

## Required measured acceptance

- All 65 DEV conversations imported once with exact original IDs/turn order/timestamps.
- No evaluation numbers appear before real successful assessment; error and missing states are distinct.
- Default sample arithmetic matches 85.38, N/A normalizes correctly, critical flag stays separate.
- Assistant follows the saved report context, displays its interpreted filters, and cannot execute arbitrary model-supplied code or SQL.
- Backend supplies every chart number and denominator. Empty/small/unevaluated cohorts remain visible.
- Metric inspection connects an aggregate to underlying assessed conversations and an assessment to source evidence.
- Custom metrics persist in the saved report and leave baseline score/export unchanged.
- Appeal/review history survives app restart; checklist changes cannot rewrite earlier evidence/snapshots.
- Teammate can consume actual OpenAPI, endpoint notes, and safe example JSON through one replaceable client layer.
- Startup on the user's laptop, frontend production build, and a representative browser workflow are verified.
- The local/cloud comparison remains a measured presentation artifact, outside product endpoints/screens.
- Private GitHub state and teammate invitation status are verified; no secrets or source payloads are tracked.
- DEV export validates; the control import/evaluate/export command is ready for organizer release. No invented control data or unapproved public release.

## Presentation reliability

Choose the final examples from real observed assessments, including a clear N/A and a reviewable criterion. Rehearse the exact prompts against the saved dataset/checklist versions. Keep prepared results and saved reports available; show pending/error states honestly if a live inference request is slow. Do not manufacture a historical trend by assigning dates based on scores.

## Rehearsal scope ruling

The primary presentation should emphasize three connected actions: a cohort question, an inspectable score, and a new report metric. Appeals and checklist versioning are required product workflows and must be verified, but can be shown as a short secondary path if the presentation slot is tight. The exact final timing and prompts require rehearsal against the actual UI.

Use explicit October2026 in prepared prompts; the current month at the event is November and the randomized demonstration dataset is October. A relative-date request must follow its real interpretation rather than silently substituting the prepared month. Explain once that dates are assigned demonstration metadata.

The initial assistant protocol accepts one operation per response. Demonstrate switching a selection and adding a metric as separate user actions, or open the prepared five-call report before requesting the new metric. Do not write a rehearsal prompt that depends on an unsupported compound action. Suggested primary prompts, pending measured smoke:

1. "Compare agent-chat quality in the first and second halves of October 2026."
2. "Now show only English conversations."
3. Open the saved five-call report, then request the operator-led next-contact boolean using its explicit true/false/N/A definition.

A baseline evaluation rerun during demonstration must be explicit and visibly pending/completed; prepared results remain available while it runs. Avoid repeating a paid bulk run merely for presentation.
