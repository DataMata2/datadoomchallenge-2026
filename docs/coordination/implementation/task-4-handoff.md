# Task 4 integration handoff

Scope: deterministic calendar/score filtering, analytics, saved reports and explicit refresh. Source/evaluation/usage documents are read-only. API status, exact optional fields and safe generated examples are in `docs/api-contract.md`, `docs/openapi.json` and `docs/api-examples.json`.

- `cqa.analytics_models` supplies strict `FilterConditions`, `FilterSpec`, `AnalysisSpec`, typed groups/chart points and observations. `cqa.analytics.select_conversations(store, filters)` returns the full ordered population with latest baseline evaluation references; `analyze(store, spec)` returns validated report output without saving or calling a model.
- `cqa.reports.Reports` supplies create/get/list/refresh; FastAPI exposes search, analytics and saved-report routes. Latest `cqa-v1` selection shares the same helper as existing JobManager, including errors. Every aggregate and chart point has a denominator; N/A and failed/missing counts remain distinct. Root IDs are the unique global selection. Optional cohorts intersect that population and can overlap. Day/night and four dayparts have separate semantics.
- Report output snapshots copy final ScoreResult and record each evaluation's revision. `stale` compares current selection/latest references/revisions and is never stored. Read operations keep saved numerical output unchanged; refresh replaces it explicitly. Opening/confirming an appeal also changes the revision even if numerical final values stay unchanged.
- Task 5 should preserve observations, snapshot definitions and root coverage when updating report context. Messages/custom metrics stay separate from regular QA; deterministic refresh preserves their existing documents and coverage rather than claiming they were recalculated. Task 5 owns custom-metric freshness/coverage semantics and the currently placeholder `custom_metrics` document type. Reports intentionally use baseline metrics/checklist cqa-v1 in this gate; mutable checklist creation remains an evaluation workflow.
- `/api/meta` derives empty/source-only/assigned/mixed provenance, actual periods and dataset counts from records. Calendar filtering uses assigned dates exclusively; source timestamps remain evidence. Source-only records stay eligible without calendar predicates and appear in `unassigned` calendar groups. Kazakhstan calendar semantics/version/source and supported predicates/groupings are published.
- Standard minimum/maximum now appear on constrained integer/float union branches in generated JSON Schema; runtime strictness is preserved. No new authentication, operator/topic analytics, provider calls, custom-metric/NLP features or source/evaluation changes are introduced here.

Meaningful verification: offline filter/analytics/report/API cases plus the existing complete backend suite. Real saved-report IDs, measured counts, invariants and commands are recorded in the Task 4 SDD report. Runtime DB and raw evidence stay ignored. Independent code review and push belong to the parent coordinator.
